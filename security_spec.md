# Security Specification: Accurate Gauging Production & Quality System

## 1. Data Invariants
1. **Zero Dummy/Mock Data**: Operational records must only be generated by authenticated users with proper roles.
2. **Identity Integrity**: Any document created or updated must bind `createdBy` / `userId` to the authenticated user ID or verified email.
3. **Model-to-Machine Invariant**: Quality operations belong strictly to `machineModel` and apply across all machines of that model, but individual check statuses in `quality_daily_checks` must be scoped by `machineNumber` and cannot mutate other machines.
4. **Strict Role-Based Access Control**:
   - `ADMIN`: Full read/write access to all collections.
   - `PLANNING`: Full access to planning modules, machine records, and work allocation.
   - `QUALITY`: Full access to quality operations, daily checklists, rejections, and re-inspections.
   - `DEPARTMENT USER`: Access scoped to their own department's work, handovers, and notifications.
   - `MANAGEMENT / VIEWER`: Read-only access to dashboards, reports, plans, machines, and quality statuses.
5. **Quality Rejection Invariant**: Rejections cannot be closed without valid corrective action and re-inspection records.
6. **Immutable Historical Records**: Deleting a quality operation with historical records must mark it `active: false`, preserving historical inspection logs.
7. **Audit Trail Immutability**: `audit_logs` entries can only be appended (created), never updated or deleted.

## 2. The "Dirty Dozen" Payloads (Designed to Fail)
1. **Unauthenticated Write**: An unauthenticated user attempting to insert or update a `machines` document.
2. **Department Spoofing**: A Department User attempting to update or complete work orders belonging to an unrelated department.
3. **Admin Role Self-Elevation**: A regular user writing `{ role: "ADMIN" }` to their `/users/{userId}` document.
4. **Junk ID Poisoning**: Attempting to create a document with a 2048-character invalid non-alphanumeric document ID.
5. **Cross-Machine Quality Mutation**: A user completing a quality check on Machine 2523 and attempting to batch-update Machine 2528.
6. **Negative Quantity Attack**: Submitting a plan with negative planned or actual quantities (`targetQuantity: -50`).
7. **Audit Log Erasure**: Attempting to delete or alter an entry in the `/audit_logs` collection.
8. **Invalid Rejection Status Jump**: Setting a Quality Rejection directly to `Closed` without corrective action or re-inspection.
9. **Notification Impersonation**: Generating a fake system notification without being signed in or without valid type.
10. **Huge Payload / Denial of Wallet**: Injecting 5MB payload into `remarks` or `description`.
11. **Document Vault Tampering**: Overwriting another user's engineering drawing without appropriate role.
12. **Unverified Email Access**: An unverified email account attempting write access to production plans.

## 3. Security Rules Testing
The `firestore.rules` file enforces authentication checks, role validations, and attribute-based security boundaries.
